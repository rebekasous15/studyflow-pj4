# ETAPA 3 — BACKLOG PRIORIZADO

## Projeto StudyFlow

O backlog apresenta as funcionalidades que ainda podem ser desenvolvidas no StudyFlow. Para organizar as prioridades, escolhemos a técnica MoSCoW.

## 1. Lista de funcionalidades

| Funcionalidade | Prioridade |
|---|---|
| Cadastrar atividades escolares | Must Have |
| Visualizar atividades cadastradas | Must Have |
| Informar datas de entrega | Must Have |
| Organizar atividades por matéria | Must Have |
| Marcar atividades como concluídas | Should Have |
| Criar lembretes de provas | Should Have |
| Personalizar as cores do sistema | Could Have |
| Criar um chat entre estudantes | Won't Have |

## 2. Justificativa das prioridades

**Must Have:** São funcionalidades essenciais para o funcionamento do StudyFlow.

**Should Have:** São importantes e melhoram a experiência dos estudantes, mas não são obrigatórias na primeira versão.

**Could Have:** São funcionalidades extras que podem ser adicionadas futuramente.

**Won't Have:** O chat entre estudantes não será desenvolvido neste momento, pois não é essencial para o objetivo principal do sistema.

## 3. Cálculo RICE

Utilizamos a fórmula:

RICE = (Alcance × Impacto) ÷ Esforço

| Item | Alcance | Impacto (1-3) | Esforço | RICE |
|---|---:|---:|---:|---:|
| Cadastrar atividades | 40 | 3 | 2 | 60 |
| Criar lembretes | 30 | 2 | 3 | 20 |

### Cálculos

**Cadastrar atividades:**

(40 × 3) ÷ 2 = 60

**Criar lembretes:**

(30 × 2) ÷ 3 = 20

## 4. Conclusão

O resultado confirmou a opinião do grupo, pois o cadastro de atividades obteve uma pontuação RICE maior. Por isso, decidimos que essa funcionalidade deve ser desenvolvida primeiro, já que é essencial para o funcionamento do StudyFlow.
